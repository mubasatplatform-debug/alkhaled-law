# ADR-0001: حدود منصة مكتب المحامي ومصادر الحقيقة

- الحالة: معتمد كخط أساس للتنفيذ
- النطاق: الإصدار الأول لمكتب محاماة واحد
- تاريخ القرار: 2026-09-15

## القرار

نطوّر المستودع الحالي كتطبيق موحّد Modular Monolith، ونحافظ على React/TanStack Start/Kysely/Better Auth الموجودة. لا نعيد كتابة النظام ولا ندخل Microservices قبل ظهور حاجة مقاسة.

## الحدود

| المجال | المالك | المصدر |
|---|---|---|
| الهوية والجلسات | Better Auth | قاعدة التطبيق |
| الموكلون والطلبات والقضايا | نطاق المكتب | Neon Postgres |
| المواعيد وساعات العمل | نطاق الجدولة | Neon Postgres |
| المحادثات وقرارات المساعد | AI Gateway + نطاق المحادثة | Neon Postgres |
| المستندات | Document Service | Postgres + Object Storage |
| الرسائل | Messaging Adapter | Twilio في الإصدار الأول |
| الفيديو | Consultation Room | WebRTC + TURN |
| الفواتير والمدفوعات | Billing Service | Neon Postgres |
| حالة الواجهة المؤقتة | واجهة المستخدم | Zustand فقط |

## قواعد عدم التعارض

1. PGLite للعرض والتطوير المحلي فقط؛ Neon هو مصدر الإنتاج.
2. Zustand لا يحفظ بيانات تشغيلية دائمة.
3. المساعد لا يصل إلى SQL مباشرة؛ يستعمل أدوات مسموحة ومحددة.
4. Twilio هو مزود الرسائل الأول؛ لا يوجد مسار موازٍ عبر Hermes.
5. n8n، إن استُخدم لاحقًا، يبقى للأعمال الثانوية ولا يملك منطق الحجز أو الصلاحيات أو الدفع.
6. كل مزود AI يمر عبر واجهة Provider واحدة.
7. كل عملية حساسة تتحقق من هوية المستخدم وملكية السجل وتكتب في سجل التدقيق.
8. لا نسجل الصوت أو الفيديو افتراضيًا.

## البدائل المرفوضة الآن

### Supabase بالتوازي مع Neon

مرفوض لأنه يضيف مصدر بيانات وصلاحيات وRealtime مزدوجة بينما المشروع يستخدم Kysely/Postgres بالفعل.

### n8n كنواة النظام

مرفوض لأن فقدان الأتمتة لا يجب أن يفسد الحجز أو يكرر الدفع أو يتجاوز الصلاحيات.

### Microservices أو إعادة كتابة كاملة

مرفوضة في الإصدار الأول لأنها تزيد نقاط الفشل وتؤخر تثبيت الرحلة الأساسية.

## خطة الترحيل

1. تثبيت CI والأمان.
2. تشغيل Neon مع نفس migrations.
3. ترحيل النماذج الموجودة في Zustand بالتتابع.
4. تشغيل AI والرسائل والفيديو فوق السجلات الدائمة.
5. إضافة الدفع بعد استقرار الفوترة اليدوية.

## اختبارات اللياقة

- استمرار الحجز بعد إعادة التشغيل والنشر.
- فشل أي محاولة وصول لملف موكل آخر.
- منع تضارب مواعيد متزامنة.
- تسجيل كل إجراء حساس في audit log.
- عدم ظهور الأسرار في build أو logs.
- عزل فشل AI أو الرسائل عن حفظ الحجز.

## نقطة المراجعة

نراجع هذا القرار إذا أصبح هناك أكثر من مكتب، أو حجم تشغيل يثبت حاجة إلى طوابير/خدمات مستقلة، أو ظهرت قيود تشغيلية لا يحلها التطبيق الموحّد.
